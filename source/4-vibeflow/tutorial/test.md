# Test - 测试阶段

## 目标

**系统级集成测试和 QA 验证，覆盖率门禁。**

Test 阶段是 VibeFlow 流程中的**最后一道质量防线**。它从用户视角验证系统是否真正工作。

---

## 核心理念

> **测试是软件的免疫系统，让缺陷无处遁形。**

单元测试验证代码本身是否正确。

集成测试验证模块之间是否协作正常。

系统测试验证整个系统是否满足用户需求。

---

## 测试类型

### Test-System（系统测试）

所有项目都必须执行：

| 测试类型 | 描述 | 覆盖率要求 |
|---------|------|-----------|
| 集成测试 | 验证模块间协作 | 100% |
| E2E 测试 | 端到端用户流程 | 关键路径全覆盖 |
| NFR 验证 | 非功能性需求验证 | 按需 |

### Test-QA（QA 测试）

仅 UI 项目执行：

- 浏览器驱动的 UI 验证
- 交互体验检查
- 视觉回归测试

## NFR 验证清单

### 性能

- [ ] 响应时间满足 SLA
- [ ] 并发用户数达标
- [ ] 资源使用率可控

### 安全

- [ ] 渗透测试通过
- [ ] 敏感数据加密
- [ ] 权限验证正确

### 可用性

- [ ] 可用性 > 99.9%
- [ ] 灾备切换正常
- [ ] 监控告警到位

### 可扩展性

- [ ] 水平扩展验证
- [ ] 数据增长应对

---

## 问题处理

### 严重/重要问题

**定义**：影响核心功能或安全性

**处理方式**：
1. 自动修复
2. 重新验证
3. 确认通过后继续

### 次要/外观问题

**定义**：不影响功能，视觉或体验上的瑕疵

**处理方式**：
1. 记录问题
2. 与用户确认是否修复
3. 用户决定是否推迟

## 实践建议

### 测试数据准备

测试前要准备好真实、可用的测试数据。

### 隔离环境

系统测试应该在**隔离的环境**中执行，避免影响生产。

### 记录测试日志

详细的测试日志对于复现和定位问题至关重要。

---

## 进入发布/反思阶段

Test 阶段通过后：

- 如果 `ship_required()` 返回 true，进入 **Ship 阶段**
- 如果 `reflect_required()` 返回 true，进入 **Reflect 阶段**

> 记住：Test 阶段的价值不在于发现所有问题，而在于确保交付给用户的系统是可靠的。
