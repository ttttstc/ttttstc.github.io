# vibeflow-plan — 计划阶段

## 概述

`vibeflow-plan` 是 Plan 阶段的入口 skill。它包含价值评审、需求编写和技术设计三个子步骤。

---

## 目标

- 选择模板、界定功能范围、获得批准
- 编写需求规范
- 产生技术设计

---

| 子技能 | 职责 |
|--------|------|
| `vibeflow-plan-value-review` | CEO 视角价值评审 |

## Plan-Value Review

### CEO 视角价值评审

**唯一关卡** — 价值评审失败 = 项目终止

#### 评审维度

| 维度 | 问题 |
|------|------|
| **价值** | 解决了什么问题？创造了什么价值？ |
| **市场规模** | 目标用户是谁？市场有多大？ |
| **竞争壁垒** | 相比现有方案，你的优势是什么？ |
| **执行风险** | 最大的风险是什么？能承受吗？ |
| **时机** | 为什么是现在？ |
| **退出策略** | 如果不 work，下一步是什么？ |

#### 评审结果

- **通过**：继续进入 Requirements 阶段
- **失败**：项目终止，记录 lessons learned

## Requirements（需求规格）

### ISO/IEC/IEEE 29148 标准

#### 模板结构

```markdown
# 需求规格说明书

## 1. 概述
### 1.1 目标
### 1.2 范围

## 2. 功能需求
### 2.1 用户故事
### 2.2 功能详细描述

## 3. 非功能需求
### 3.1 性能需求
### 3.2 安全需求
### 3.3 可用性需求

## 4. 验收标准
```

### 用户故事模板

```
作为 [角色]
我希望 [功能]
以便 [价值]
```

### 验收条件模板

```markdown
## 需求：用户登录

### 验收条件
1. 用户输入正确用户名和密码 → 登录成功
2. 用户输入错误密码 → 显示"密码错误"
3. 用户输入不存在用户名 → 显示"用户不存在"
4. 连续 5 次登录失败 → 锁定账户 15 分钟
```

## Design（技术设计）

### 设计流程

```
0. [可选] 问题探索 ── vibeflow-brainstorming
1. 读取 SRS + UCD
2. 探索上下文
3. 提出方案
4. 用户逐节审批
5. AI 深度评审（工程 + 设计）
6. 范围决策（Expand / Hold / Reduce）
7. 编写设计文档
```

### 三视角评审

| 视角 | 时机 | 关注点 |
|------|------|--------|
| CEO | Plan 阶段 | 价值 |
| 工程 | Design 阶段末尾 | 可行性、架构、代码质量 |
| 设计 | Design 阶段末尾 | 体验、信息架构、交互 |
