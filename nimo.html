The missing engineering layer

从“它能写代码”，
到“这件事做成了”。

模型带来能力，工具让它动手。工程方法负责把能力组织成一次完整交付：控制范围、选择做法、核验结果，把经验留给下一次。

01 / DIRECTION

把任务带回目标。

先判断是讨论还是执行，明确范围与完成条件。按任务选择 Playbook，把工程原则带进每一步，而不是在最后补一句“请保证质量”。

目标 × 原则 × 任务流程
02 / COORDINATION

能力可以换，标准不换。

按步骤调用合适的 Skill。需要协作时，把目标、边界和验收条件一起交给子 Agent，主 Agent 再核对交付。

宿主运行 × SKILL 执行 × 主 AGENT 验收
03 / CONTINUITY

下一次，从已有认识出发。

项目知识帮助判断，真实验证支撑结论。项目发生变化后，识别知识影响；需要时再审计与维护，让经验有依据地积累。

项目知识 × 验证资产 × 持续改进

Control the method

在模型与工具之上，
把工程方法接起来。

nimo 用 Mode 作为入口，用 Playbook 组织步骤，直接引用 Skill 完成工作。模型推理、工具调用和权限执行仍由宿主承担。

你可以换执行能力，也可以换工作环境。任务目标、工程要求和交付标准，不必跟着重写。

Harness 控制层，控制的是什么？

nimo 组织任务决策、工程流程、能力调用与验收要求。它通过宿主执行这些约定，不是独立 Agent Runtime，也不直接运行模型或工具。

能保证 Agent 不越界吗？

工程方法约定不能替代安全沙箱。不可绕过的权限与质量门禁，应由宿主权限、CI、仓库保护或发布平台强制执行。

必须使用某个模型或研发 Skill 吗？

工程方法与执行能力分层，允许按任务与环境选择 Skill。宿主是否支持具体调用方式，需要实际核对，不能把设计支持当成运行验证。

会自动改我的项目知识吗？

普通任务会做轻量知识影响判断，不自动触发审计。知识审计为只读，知识维护按明确授权进行；历史证据也不代表当前版本已经通过验证。
