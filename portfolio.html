框架 · Framework

VibeFlow —— 让 AI 按工程纪律交付

一个面向 Claude Code 的结构化交付框架。把需求、设计、实现、审查、测试、发布和复盘串成一条可恢复、可追踪、可自动继续的工作流：前半程你拍板，后半程系统自己推进，卡住了再回来问你。

Claude Code工作流文件即状态TDD

核心能力

  • 8 阶段结构化流水线 — 需求 → 设计 → 实现 → 审查 → 测试 → 发布 → 复盘，每阶段有明确的输入/输出契约和质量门禁
  • 文件即状态 — 所有中间产物（spec、design doc、task list、review notes）以 Markdown 文件落盘，对话中断后可从任意断点恢复
  • 冻结/解冻机制 — 关键决策点用 freeze/unfreeze 锁定上下文，防止 AI 在后续步骤中"创造性地"偏离已确认的方向
  • TDD 驱动实现 — 先写测试再写实现，测试即规格，AI 生成的代码必须通过预定义的验收标准
  • 多角色协作 — 内置 Coder（执行）、Codex（审核）、Gemini（设计顾问）三种 AI 角色，按阶段自动切换

技术架构

VibeFlow 采用 状态机 + 文件系统 的混合架构：每个阶段是一个状态节点，状态转换由 Skill 文件定义（vibeflow-*.md），所有上下文通过 .vibeflow/ 目录下的结构化文件持久化。框架本身不运行服务——它是一套 Claude Code Skills，通过对话循环驱动。

设计决策：拒绝引入数据库或运行时依赖。文件系统是最可靠的"数据库"——Git 可追踪、人类可阅读、任何编辑器可修改。

适用场景

需要 AI 参与但不信任 AI "自由发挥"的团队。VibeFlow 的核心价值不是让 AI 写更多代码，而是让 AI 写的代码可审计、可回滚、可解释。

工具 · Tool

understand-arch —— 让 AI 真正读懂你的代码

一个 Claude Code 架构助手，能扫描真实代码仓库、构建知识图谱、推断架构意图，并将架构知识转化为文档、评审意见、图表和仪表盘。不是一次性快照——架构知识随代码演进而持续更新。

代码分析知识图谱架构评审Claude Code

核心能力

  • /arch-onboard — 扫描代码仓库、构建知识图谱、推断架构，快速建立全局理解
  • /arch-design — 根据 PRD 或变更请求生成三档候选方案（最小 / 改进 / 长期演化），由高级审核子代理交叉检查
  • /arch-audit — 对比基线架构与当前代码状态，发现架构漂移
  • /arch-wiki — 生成 14 章架构文档，支持多受众模式（CTO / 新人 / PM / 架构师视角）
  • /arch-diagram — 输出 SVG / PNG / PlantUML / Mermaid 架构图

技术架构

基于 Claude Code 的对话循环运行，核心是确定性代码扫描引擎（源自 Understand-Anything）+ AI 推断层的双层架构。扫描引擎负责提取符号、依赖、调用关系等结构化数据；AI 层在此基础上推断意图、生成文档和设计方案。

知识库是"活的"——从日常 commit、Code Review、ADR（架构决策记录）中持续学习，而非一次性快照。所有输出存储在 .understand-arch/{project}/ 下，不污染仓库根目录。

跨运行时安装器支持 Codex、Cursor、VS Code Copilot 等多个 AI 编码工具。

适用场景

需要快速理解遗留系统、做架构评审、生成 onboarding 文档的团队。尤其适合新成员入职、跨团队代码交接、架构合规审计。

桌面应用 · Desktop

巡塔 · Tower —— 当项目管理长出了山水

一个用国风 + 黑神话美学把项目管理从列表/看板重塑为沉浸式塔楼空间体验的本地优先桌面应用。拒绝退化成 SaaS 后台——每个组件都必须回答"它属于山水、书架、卷轴还是纸页"。

ElectronReact 19国风美学本地优先

核心能力

  • 五层塔模型 — 愿景层（星殿）、协同层（书院）、实现层（禅房）、基础设施层（工坊）、设计层（佛堂），每层有独立情绪和场景
  • 三条叙事线 — 事项推进（藏经阁书架）、风险管理（妖关图妖怪战斗）、里程碑（群像殿 28 神像），用叙事代替进度条
  • 塔林 — 多项目并存，山水画中散落多座塔，每座塔是一个独立项目
  • Excel 往返 — 导入导出 Tower.xlsx 全字段无损，兼容传统协作流程
  • 全离线 — 数据存于 ~/Documents/Tower/tower.json，零网络依赖

技术架构

React 19 + TypeScript + Vite 7 构建 UI 层，Electron 42 + electron-builder 打包为桌面应用（NSIS 安装器，< 200MB）。状态管理用 Zustand 5 + immer + persist，数据持久化到本地 JSON 文件。

视觉层采用预渲染序列帧 + CSS steps() + 4 层视差实现塔楼运镜——不是 Three.js，不是 Canvas，是纯 CSS 动画。设计系统用自研 CSS Design Token，不依赖 Tailwind 或组件库。

测试策略：Vitest（单元）+ Playwright（E2E），覆盖核心数据流和交互路径。

适用场景

受够了 SaaS 后台千篇一律的 PM、设计师、技术负责人。Tower 不是一个"更好看的看板"——它是一种不同的项目管理心智模型：用空间感代替列表，用叙事代替进度条，用美感代替焦虑。

技能套件 · Skill Suite

ni-skill —— 从选题到发布的端到端文章流水线

面向技术创作者的 Claude Code 技能套件，覆盖从选题研究到微信公众号发布的完整文章生产链路。每个技能可独立使用，也可被编排为自动化流水线。

Claude Code Skills内容创作微信公众号自动化

核心能力

  • 6 阶段流水线 — ni-research（趋势分析）→ ni-insight（核心论点）→ ni-writer（写作）→ ni-formatter（排版）→ ni-inspect（质检）→ ni-draft（推送微信草稿箱）
  • 5 种文章原型 — 动手评测、速读摘要、工程手册、技术论战、个人随笔，各有字数和灵魂定义
  • ni-url2md — 支持 JS 渲染 + 登录态页面抓取，解决传统爬虫抓不到 SPA 内容的问题
  • 断点续写 — ni-article-workflow 串联全流程，任何阶段中断后可从断点恢复
  • 自验证 — 每个技能内置质检逻辑，输出前自动检查格式、长度、引用完整性

技术架构

基于 Claude Code 技能系统构建，每个 Skill 是一个独立的 Markdown 指令文件，通过对话循环驱动。流水线编排层（ni-article-workflow）负责阶段衔接和状态传递。

外部依赖最小化：Python 3.10+ 用于微信公众号 API 推送（ni-draft），Node.js + Chrome 用于网页抓取（ni-url2md），其余全部在 Claude Code 对话内完成。

三条设计准则贯穿始终：诚实输出（不编造）、自验证（每技能自检）、显式降级（外部依赖不可用时明确标记而非静默失败）。

适用场景

需要高效产出高质量技术文章的个人创作者，尤其写 AI、工程管理、架构主题。从选题到发布全程自动化，同时保留人工审核和风格控制的节点。
